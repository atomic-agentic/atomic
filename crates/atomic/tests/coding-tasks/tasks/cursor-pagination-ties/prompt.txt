Exports from this ticket store lose tickets. `python3 -m tickets count data/tickets.json` says there are 37, but `python3 -m tickets export --page-size 10 data/tickets.json` reports "exported 31 tickets", and other page sizes lose a different number; with --page-size 100 all 37 come out. Find the cause and fix it, so that following the cursors of tickets.api.list_tickets from the first page to the last returns every matching ticket exactly once, in the order README.md gives, for every page size from 1 to 100 and with or without a status filter, and so that `export` writes them all. Every page but the last must stay full, and the last page must have no next cursor. Cursors are opaque, so you may change what is inside them; cursors made before your change need not keep working. Do not change the tests in tests/; run them with: python3 -m unittest discover -s tests -t .
