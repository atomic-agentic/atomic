Our log collector rejects some of the lines logship produces, and only ones with non-ASCII text in them: some are too long for the collector's byte limit, and some show the Unicode replacement character where the text was cut. Lines in plain ASCII are fine. You can see it with: python3 -m logship --config examples/logship.conf examples/records.jsonl. Fix logship so that every line follows the rules for the line limit in README.md, whatever text is in the host name, the app name or the message, and so that lines in plain ASCII come out exactly as they do now. Run the tests with: python3 -m unittest discover -s tests -t .
