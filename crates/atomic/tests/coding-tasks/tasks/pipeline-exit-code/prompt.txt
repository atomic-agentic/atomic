The nightly pipeline in this repository does not report failures. Running `sh run.sh data/bad` prints ERROR lines from the validate stage, yet it goes on through transform and load, prints "pipeline ok" and exits 0; running a stage on its own, as in `python3 validate.py data/bad out` after extract, exits 0 too. Make the pipeline follow the rules in README.md: a stage that logged any ERROR, from the stage itself or from one of the shared modules in pipeline/, exits 1, and run.sh stops at the first failed stage, prints `pipeline failed: <stage>` to stderr and exits 1, with the stages after it not run. Keep everything else as it is: the log format, each stage's output in OUT_DIR/<stage>.log and on the terminal, and `pipeline ok` with exit 0 when every stage passes. Do not change the files in data/. Run the tests with: python3 -m unittest discover -s tests -t .
