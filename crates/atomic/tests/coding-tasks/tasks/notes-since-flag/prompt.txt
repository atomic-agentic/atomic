Add a `--since YYYY-MM-DD` option to both the `list` and the `export` commands of the notes tool (python3 -m notes). It keeps only notes created on that day or later, by the day of each note's created timestamp in UTC, as the tool shows days everywhere else: a note stored as 2026-03-04T23:30:00-02:00 was created on 2026-03-05. It combines with --tag and --text as they combine with each other, and --limit still applies after every filter. A value that is not a valid date in YYYY-MM-DD form must make the command exit with status 2 and an error message that names --since, as other bad arguments do. Do the filtering through a new keyword argument `since` of the existing filter_notes function in notes/query.py, which takes a datetime.date, or None for no filter, and use it from both commands. Existing calls to filter_notes, including ones that pass its current arguments by position, must keep working unchanged. Show the option in each command's --help, and document it in the Usage section of README.md. Add tests for since to tests/test_query.py that would catch a filter_notes that ignores it. Run the tests with: python3 -m unittest discover -s tests -t .
