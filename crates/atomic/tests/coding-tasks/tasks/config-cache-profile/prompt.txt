In this pricing tool, `python3 -m pricer batch data/jobs-example.txt` prices some lines wrongly: the eu and jp lines come out in USD with US tax, although the same job run alone, as in `python3 -m pricer quote --profile eu WIDGET-S 3`, is right. `python3 -m pricer profiles` looks wrong too. Find the cause and fix it, so that every line of a batch, whatever mix of profiles it has, is exactly what `quote` prints for that job alone, and so that environment overrides (README.md) still apply to their own profile only. Loading settings is slow in production, so keep it cached: in one process, each profile's file under config/profiles/ must be read at most once, however many jobs use that profile. Do not change the tests in tests/; run them with: python3 -m unittest discover -s tests -t .
